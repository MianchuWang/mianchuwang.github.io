RoPE injects position by rotating pairs of features instead of adding a vector. The payoff falls out of the algebra: after rotating queries and keys, their dot product depends only on the distance between the two positions.

Take the features two at a time — the pair (x[2i], x[2i+1]) — and rotate it by $\theta_i = \mathrm{pos}\cdot\mathrm{base}^{-2i/d}$:

$$\begin{aligned} \mathrm{out}_{2i}\phantom{{}+1} &= x_{2i}\cos\theta_i - x_{2i+1}\sin\theta_i\\ \mathrm{out}_{2i+1} &= x_{2i}\sin\theta_i + x_{2i+1}\cos\theta_i \end{aligned}$$

  • x — (..., n, d_head) with d_head even
  • positions — integer array (n,); usually arange(n), but with a KV cache it starts at the cache length
  • theta — the base, default 10000.0

Return the same shape as x. Note the pairing is interleaved (neighbouring features), not split-half — both conventions exist in the wild.

Hint

Build the angles once as (n, d_head/2) via an outer product of positions and frequencies, then reshape x to (..., n, d_head/2, 2) — rearrange(x, "... n (p two) -> ... n p two", two=2) — rotate, and flatten back. Position 0 must leave the vector unchanged.
