At inference the KV cache, not the weights, is what fills memory. GQA shrinks it: keep all num_heads query heads, but project only num_kv_heads key/value heads and share each one across a group of queries. num_kv_heads == num_heads is plain MHA; num_kv_heads == 1 is multi-query attention.

  • x — (b, n, d_model), and d_head = d_model // num_heads
  • Wq — (num_heads * d_head, d_model)
  • Wk, Wv — (num_kv_heads * d_head, d_model)  ← the narrow ones
  • Wo — (d_model, num_heads * d_head)
  • mask — boolean (n, n) or None

Query head i uses KV head i // (num_heads // num_kv_heads): the first group of queries shares KV head 0, the next shares KV head 1, and so on. Return (b, n, d_model).

Hint

Rather than looping over groups, broadcast the KV heads back up: repeat(k, "b kh n d -> b (kh g) n d", g=num_heads // num_kv_heads). Note that (kh g) — not (g kh) — is what puts query head i with KV head i // g.
